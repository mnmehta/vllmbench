# Disabling vLLM Prefix Cache

## Overview

You can now disable vLLM's prefix caching feature by setting `disable_prefix_cache: true` in your Hydra configuration. This is useful for:

- **Testing scheduler behavior**: See how the endpoint picker scores pods without prefix cache affinity
- **Comparing performance**: Measure the impact of prefix caching on your workload
- **Debugging**: Isolate issues related to prefix caching
- **Fair comparison**: Ensure all pods are scored purely on resource availability (KV cache, queue size, etc.)

## How It Works

When `disable_prefix_cache: true` is set, the `install_llmd.py` script adds the `--no-enable-prefix-caching` flag to the vLLM container arguments. This prevents vLLM from caching prefix blocks, which means:

1. **No prefix cache hits**: Requests won't benefit from cached prompt prefixes
2. **Different scoring**: The endpoint picker's prefix cache scorer will give all pods a score of 0 for prefix affinity
3. **Pure resource-based routing**: Pod selection is based only on KV cache utilization, queue size, and running requests

## Configuration

### Default Behavior (Prefix Cache Enabled)

```yaml
# conf/default.yaml
install:
  disable_prefix_cache: false  # default
```

### Disabling Prefix Cache

#### Option 1: Via Hydra Config Override

```yaml
# conf/gptoss120b_no_prefix_cache.yaml
defaults:
  - default
  - _self_

install:
  disable_prefix_cache: true
```

Then run:
```bash
python install_llmd.py --config-name=gptoss120b_no_prefix_cache
```

#### Option 2: Via Command Line Override

```bash
python install_llmd.py --config-name=gptoss120b install.disable_prefix_cache=true
```

#### Option 3: Update Existing Config

Edit your existing config file (e.g., `conf/gptoss120b.yaml`):

```yaml
install:
  namespace: "llm-d-bench"
  helmfile_overrides:
    - override_ms_gptoss120b.yaml
  decode_replicas: 8
  decode_tp: 1
  disable_prefix_cache: true  # Add this line
```

## Impact on Endpoint Scoring

### With Prefix Cache (Default)

The endpoint picker scores pods based on multiple factors:
- **Prefix Cache Affinity** (weight: 3): Higher score for pods with matching cached prefixes
- **KV Cache Utilization** (weight: 5): Higher score for pods with lower KV cache usage
- **Queue Size**: Higher score for pods with shorter queues
- **Running Requests**: Higher score for pods with fewer running requests

**Result**: Requests are routed to pods that have previously processed similar prompts, even if those pods are slightly more loaded.

### Without Prefix Cache (`disable_prefix_cache: true`)

The endpoint picker scores pods based only on resource availability:
- **Prefix Cache Affinity** (weight: 3): All pods score 0 (no cache hits)
- **KV Cache Utilization** (weight: 5): Higher score for pods with lower KV cache usage
- **Queue Size**: Higher score for pods with shorter queues
- **Running Requests**: Higher score for pods with fewer running requests

**Result**: Requests are distributed purely based on current resource availability, leading to more even load balancing.

## Implementation Details

### Code Changes

**File: `conf/default.yaml`**
```yaml
install:
  disable_prefix_cache: false  # New parameter
```

**File: `install_llmd.py` (line 160)**
```python
disable_prefix_cache = bool(getattr(cfg.install, "disable_prefix_cache", False))
```

**File: `install_llmd.py` (dynamic override generation)**
The script generates a temporary Helm values override file instead of hardcoding argument indices:

```python
# Build a dynamic values override for vLLM args and env (avoids hardcoding indices)
temp_override_path = None
if decode_tp > 1 or disable_prefix_cache:
    override_data = {"decode": {"containers": [{"name": "vllm"}]}}
    container = override_data["decode"]["containers"][0]

    # Append extra vLLM args
    extra_args = []
    if decode_tp and decode_tp > 1:
        extra_args.extend([
            "--tensor-parallel-size",
            "$(TP_SIZE)",
            "--distributed-executor-backend",
            "mp"
        ])
    if disable_prefix_cache:
        extra_args.append("--no-enable-prefix-caching")

    if extra_args:
        container["args"] = extra_args

    # Override CUDA_VISIBLE_DEVICES if TP > 1
    if decode_tp and decode_tp > 1:
        cuda_devices = ",".join(str(i) for i in range(max(decode_tp, 1)))
        container["env"] = [{"name": "CUDA_VISIBLE_DEVICES", "value": cuda_devices}]

    # Write temporary override file
    fd, temp_override_path = tempfile.mkstemp(suffix=".yaml", prefix="llmd_override_")
    with os.fdopen(fd, 'w') as f:
        yaml.dump(override_data, f)
```

### Dynamic Override Approach

**Why this is better than hardcoded indices:**

1. **Robust to base values changes**: If the base `values.yaml` adds or removes args, this still works
2. **Clean YAML merge**: Helm's strategic merge properly appends the args array
3. **No index math**: We don't need to track which index to use
4. **Self-documenting**: The generated override file shows exactly what's being changed

**Example generated override file** (with TP=2 and prefix cache disabled):
```yaml
decode:
  containers:
  - name: vllm
    args:
    - --tensor-parallel-size
    - $(TP_SIZE)
    - --distributed-executor-backend
    - mp
    - --no-enable-prefix-caching
    env:
    - name: CUDA_VISIBLE_DEVICES
      value: 0,1
```

When Helm merges this with the base values, it **appends** these args to the existing args array, regardless of how many base args exist.

### Cleanup

The temporary override file is automatically deleted after the helmfile command completes.

## Troubleshooting

### Issue: Prefix cache still appears to be working

**Check:**
1. Verify the deployment used the correct config: `oc get pod <pod-name> -o yaml | grep -A 10 args`
2. Ensure you destroyed the old deployment first: `install.destroy_first: true`
3. Check vLLM logs for confirmation: `oc logs <pod-name> -c vllm | grep prefix`

### Issue: Performance is slower without prefix cache

**This is expected.** Prefix caching provides significant performance benefits when requests have overlapping prompts. If disabling it results in slower performance, it confirms that your workload benefits from prefix caching.

### Issue: Pods still showing different scores in EPP logs

**This is expected.** Disabling prefix cache only affects the **prefix cache scorer**. Pods will still have different scores based on KV cache utilization, queue size, and running requests.
